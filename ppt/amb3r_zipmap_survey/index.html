02 / 16
共同背景

DUSt3R/VGGT 之后，问题从“能不能直接预测 3D”变成“如何更准、更大、更稳”。

pointmap 范式已经把深度、位姿、匹配和重建统一到稠密 3D 回归中。但多视角融合、真实尺度、大规模图像集合和在线建图仍有明显缺口。

空间表示

2D token 不等于 3D 融合

多个像素对应同一 3D 点时，纯 2D grid 推理缺少显式空间紧凑性。

尺度

pointmap 常有尺度歧义

很多重建结果需要 median-scale alignment，离真实 metric reconstruction 仍有距离。

复杂度

全局 attention 随 N² 增长

VGGT、pi^3 类强模型在几百帧场景下开销迅速变重。

系统性

VO/SfM 不只是单次预测

在线、长序列、无内参、无 BA 的完整流程仍需要额外设计。

AMB3R 回答“如何让 pointmap 模型更像一个真正的 3D 几何系统”；ZipMap 回答“如何让强前馈 3D 模型处理几百帧而不爆炸”。
定位
空间紧凑性 · 度量尺度 · 线性时间

为什么需要 backend

pointmap 输出有 3D 坐标，但网络内部未必在 3D 空间思考。

AMB3R 的核心批评是：DUSt3R/VGGT 这类模型虽能让多个像素回归到相近 3D 点，但它们主要在 2D 特征网格上做 attention，缺少“同一个 3D 坐标只能有一个属性”的结构约束。

多视角观测

同一个墙角、桌面边缘或地面点，会在多张图像中重复出现。

pointmap 回归

每个像素预测 3D 坐标，但融合主要依赖网络隐式学习。

稀疏体素后端

把对应点落入相同或相邻 voxel，显式合并多视角特征。

空间紧凑性

同一空间位置共享一个 fused feature，减少跨视角不一致。

这就是 AMB3R 名字里“Backend”的含义：不是传统 BA 优化器，而是可学习的 3D 空间融合后端。
核心矛盾
2D grid inference vs. compact 3D representation
AMB3R · 模型结构
05 / 16
Pipeline

冻结 VGGT，把“3D 融合能力”作为轻量后端接进去。

VGGT front-end

预测 pointmaps、camera/depth、visual/geometric features；主干冻结。

Sparse voxelization

把 pointmap 与几何特征投到 sparse voxel grid；voxel 内平均融合。

3D transformer

space-filling curve 序列化 voxel；Point Transformer v3 风格 U-Net 推理。

Zero-conv injection

KNN 插值回像素/点，再通过 zero convolution 注入 VGGT decoder。

为什么冻结

保留 confidence 函数

论文指出 confidence 与训练分布/recipe 强相关，随意微调可能 catastrophic forgetting。

为什么 zero-conv

低风险接入新后端

类似 ControlNet 的注入方式，让新后端从近似零影响开始学习。

为什么 sparse voxel

复杂度跟 3D 内容相关

相比完整体素立方增长，稀疏结构更适合可见表面和室内外重建。

结构
Frozen front-end · sparse voxel backend · KNN · zero-conv

Metric-scale Reconstruction

尺度头不回归“整组图像的全局 scale”，而回归每帧可恢复的 metric log depth。

直接全局尺度
依赖所有帧组合，受帧顺序和 frame set 变化影响，论文认为难训练且易过拟合。
avoid
AMB3R 选择
每帧选预测深度中位数对应像素，回归其 metric log depth；推理时取多帧 scale 中位数。
scale
监督细节
使用 encoder feature 加 depth DPT branch feature；缺失深度时用 ROE solver 获得相对尺度监督。
ROE
NYUv2
zero-shot monocular depth 表中 AMB3R rel 3.0，优于 VGGT 3.6。
RMVDB
multi-view depth 平均 rel 1.7，论文报告为新 SOTA。
DTU
玩具建筑/白桌背景会诱发尺度误判，论文专门提示此类 failure。
Metric
不只是对齐后好看，而是尝试恢复真实世界尺度。
尺度
per-frame metric log depth · median scale
AMB3R · VO 与 SfM
07 / 16
System Extension

只按多视角重建训练，却扩展到无标定 VO 和大规模 SfM。

Uncalibrated Visual Odometry

keyframes 作为 active memory

输入新帧和 active keyframes；利用 pointmap 输出在参考帧坐标系下、只差未知尺度的先验，先估计相对 scale，再通过 keyframes 的相对位姿加权平均对齐到全局。论文强调避免显式 Kabsch-Umeyama 刚体对齐，并在 confidence 足够时可跳过 backend。

Feed-forward SfM

cluster -> register -> mapping

先用图像特征聚类成小簇，再从高置信簇初始化，全局 keyframe list 逐步扩张；之后做 keyframe refinement 和 non-keyframe refinement。整个流程不做传统 BA，因此是 feed-forward SfM，而非优化式 SfM。

VO 速度

4.2 FPS

RTX 4090、392x518、TUM，best 6.0 / worst 3.4 FPS；active keyframes 上限 10。

TUM VO

2.7 cm

AMB3R(KF) 平均 ATE RMSE；论文报告优于 MUSt3R 和多种 VO/SLAM 基线。

ETH3D VO

2.0 cm

ETH3D SLAM 上 AMB3R(KF) 平均 ATE RMSE，明显优于 MUSt3R 表中结果。

系统
keyframe memory · coordinate alignment · no BA

为什么要线性时间

全局 attention 很强，但几百张图像时成本过高。

VGGT、pi^3 等模型通过全局交互建立跨视角一致性，质量高但复杂度随输入图像数二次增长。CUT3R、TTT3R 等顺序方法能线性扩展，但常因为局部/递归处理损失质量或累积误差。

ZipMap · TTT fast weights
11 / 16
Method

用 Test-Time Training layer，把图像集合“写入”MLP fast weights。

DINOv2 tokens

图像 resize/tokenize 后进入 DINOv2 encoder，得到 patch-level tokens。

Local window attention

保留每帧局部空间建模，避免完全丢掉图像内结构。

Large-chunk TTT

不存所有 token，而是用梯度更新把上下文写进 nonlinear fast-weight function。

3D heads + state query

一次输出 pose/depth/pointmap；同一状态可用 ray map 查询新视角。

Backbone

24 layers

每层交替 local window attention 和 TTT block。

State size

6d² per layer

d=1024，fast-weight MLP intermediate dimension=2048。

Ablation

gated unit + Newton-Schulz

去掉 gated unit、Newton-Schulz 或动态 token learning rate 都会降低 ETH3D point-map 指标。

机制
local detail + global compressed state

Runtime + Accuracy

长序列优势是 ZipMap 最有辨识度的结果。

论文和项目页报告：在单张 H100 上，ZipMap 可用低于 10 秒处理 700+/750 帧，约 75 FPS；相较 VGGT 在长序列下快 20x+，相较 pi^3 快 15x+。

ZipMap · Scene State 与 Streaming
14 / 16
Stateful Representation

ZipMap 的 state 不只是缓存，它是可查询的隐式场景表示。

Scene State Query

给定 query camera / ray map，输出新视角点图

输入图像集合被压缩为 TTT fast weights 后，可以在 novel camera 条件下直接 query RGB、depth 和 colored point map。论文强调它主要用于生成 colored point clouds，不声称达到 unposed NVS SOTA。

Streaming Reconstruction

逐帧更新 TTT state

streaming 版本替换 camera head 为轻量 MLP，并在 32 H100 GPUs 上 fine-tune。作者报告在 video depth、camera pose、point-map reconstruction 上通常优于 CUT3R 和 TTT3R。

最值得记住的一点：ZipMap 把“长上下文重建”转成了“学习如何写入和读取场景状态”的问题。
状态
queryable state · colored point map · streaming update

Limitations

线性时间解决的是可扩展性，不自动解决所有几何系统问题。

超长分布外
当场景规模远超训练分布，模型仍会明显退化；作者认为这是现有 feed-forward 方法共同问题。
OOD
NVS 不是主目标
query RGB 在高频区域会模糊，当前更适合 colored point clouds，不是高保真 novel view synthesis。
NVS
短序列常数开销
5 帧左右很短输入时，TTT block 和 Newton-Schulz 可能比高度优化的 FlashAttention 基线略慢。
cost
隐式状态可控性
fast weights 是压缩状态，不等价于传统 SLAM map；可编辑性、约束注入、闭环修正仍是后续问题。
map
所以 ZipMap 的最佳定位：长图像集合/长视频前馈重建的高吞吐基础模型，而不是完整替代所有优化式 3D 系统。
边界
scale beyond training · blurry query RGB · implicit state
